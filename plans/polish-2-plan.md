# Полировка 2: узел внутри процесса, левая полоса, состояние окна, панель

Основа — `master` на `7e3c99e`. Решения согласованы с оператором; проверки только на этой машине
и точечно, эмуляторы не запускаются. Перед коммитом — `nix flake check`.

Имя локального узла в данных остаётся `default` (`ui.tabs`, сокет, CLI). «inprocess» — только
подпись его строки в окне, которое держит узел; в остальных окнах и у узла-службы — `default`.

## A. Пустая строка перед записями — как в pi

- Причина: `TranscriptView` (`packages/tui/src/transcript.ts`) вызывает отрисовщик записи
  расширения напрямую; pi оборачивает его в `CustomEntryComponent`
  (`modes/interactive/components/custom-entry.js`), который ставит `Spacer(1)`, отступ вывода
  и передаёт `keyText`/`keyHint`. Компонент не экспортирован из пакета pi.
- `packages/tui/src/pi-internals.ts`: загрузка `CustomEntryComponent`; путь добавляется в
  `PI_INTERNAL_MODULES` и в `pi-internals.test.ts`.
- `TranscriptView` рисует записи расширений и harness через него (`setExpanded`, `outputPad`,
  `hasContent()`); запись, пришедшая во время стриминга, встаёт перед текущим ответом, как в
  `addCustomEntryToChat` pi.
- Проверка: сценарий TUI — между прерванным bash, баннером «interrupted» и следующим сообщением
  есть пустая строка.

## B. Клавиши

- Ctrl+Q — выход из TUI (`app.quit`, как сейчас).
- Ctrl+D при пустом редакторе закрывает вкладку сессии (`tabs.close`); при непустом —
  `deleteCharForward` редактора pi.
- Ctrl+W у `tabs.close` убирается (в редакторе pi он удаляет слово).
- Ctrl+C только очищает редактор, когда фокус в нём. Глобальный обработчик в `App.onKey`,
  двойное нажатие, `quitArmed` и уведомление «Ctrl+C again to quit» удаляются. В диалогах pi
  Ctrl+C остаётся отменой (это поведение самого pi).
- Web: Ctrl+D при пустом поле закрывает вкладку (с `preventDefault` только в этом случае);
  Ctrl+C не перехватывается.
- Правки: `packages/client/src/keymap.ts`, `installKeybindings` (`app.exit`, `app.clear`),
  `App.onKey`, `packages/app/src/keyboard.web.ts`, подсказки и `docs/`.
- Проверка: сценарий TUI — Ctrl+C очищает и не выходит; Ctrl+D с текстом удаляет символ, без
  текста закрывает вкладку; Ctrl+Q выходит.

## C. Локальный узел внутри процесса

### Держатель и клиенты

- Первый клиент (`harness`, `harness web-app`) поднимает узел у себя в процессе и слушает
  `~/.harness/sockets/default.sock`; сам работает с ним через in-process транспорт, остальные —
  через сокет.
- Рукопожатие узла сообщает `host: "client" | "service"` (протокол: `hello`/`node_info`, схема,
  справочник). Служба — любой `harness node …`, запущенный отдельной командой (user systemd,
  NixOS-модуль, s6 на Fly). Если на сокете служба — клиенты свои узлы не поднимают.
- `localNode` в `packages/cli/src/main.ts` переписывается под эту схему; общая логика
  «подключиться или стать держателем» — в `packages/node/src/local.ts` (CLI и web-app).

### Смена держателя

- Все клиенты видят обрыв одновременно.
- Был `host: "service"` — только переподключаются (служба поднимается своим супервизором).
- Был `host: "client"` — выборы: атомарное создание `~/.harness/locks/node-default.lock`
  (`open wx`, внутри PID). Создавший поднимает узел у себя; остальные переподключаются к сокету
  со случайной задержкой, пока узел не ответит. Lock с мёртвым PID — брошенный, удаляется. Lock
  снимается при закрытии узла.
- Переподключение главного подключения клиента (`packages/client/src/connection.ts`,
  `ClientModel`) получает фабрику «подключиться или стать держателем».
- После переподключения — строка статуса: «node default moved to another window; N sessions
  were interrupted» (N — вкладки, чьи агенты работали до обрыва).
- Вкладки поднимают агентов из файлов сессий (`ensureAgent`, как сейчас).

### Выход держателя

- Ctrl+Q у держателя выходит сразу, если нет работающих агентов и других клиентов. Иначе — на
  месте редактора подтверждение «Quitting stops N running agents (M other windows use this
  node)»: Quit / Cancel.
- Подсказка «агенты продолжают работать на узле» остаётся только при закрытии вкладки и для
  узла-службы.

### Версии

- Если версия локального узла ≠ версии клиента — клиент выходит с ошибкой при подключении и при
  каждом переподключении:
  `harness <версия клиента>: node default runs harness <версия узла> (held by window PID N | a service); close it or restart the service`.
- Удалённые узлы: только проверка совместимости протокола, как сейчас.

### Restart node

- Строка «restart node» в секции HARNESS панели; после подтверждения на месте редактора
  («Restart node <имя>? Stops N agents and their background tasks»: Restart / Cancel).
- Новая операция узла `node_restart` (протокол, схема, справочник). Держатель-клиент
  останавливает агентов и их процессы и поднимает узел заново в том же процессе; служба
  завершается и поднимается своим супервизором. Клиенты переподключаются.
- Права: собственный пользователь узла или админ hub.

### Удаляется

- Ничего от варианта с фоновым процессом не вводится (нет `node.log`, таймаутов, запуска узла
  из переподключения).

### Документация

- `docs/operations/nodes.md`: держатель, выборы, служба, пример user unit для systemd с
  `harness node default`; ошибка версии и что делать.

### Проверки

- Два TUI: первый закрылся — второй стал держателем, его вкладки снова работают.
- Три клиента теряют держателя одновременно — поднимается ровно один узел.
- Узел-служба падает — клиенты своего узла не поднимают.
- Ctrl+Q у держателя при работающем агенте спрашивает подтверждение.
- Клиент другой версии выходит с ошибкой.
- `node_restart`: агенты остановлены, клиенты переподключились.

## D. Ctrl+V — как в pi

- Привязка `app.clipboard.pasteImage` в зоне редактора TUI.
- Чтение буфера — функции pi через `pi-internals.ts` (`utils/clipboard.js`:
  `readClipboardFilePaths`, `readClipboardText`; `utils/clipboard-image.js`:
  `readClipboardImage`, `extensionForImageMimeType`).
- Порядок, как в `handleClipboardPaste` pi:
  1. пути файлов: сессия на этой машине — вставить как есть (пробелы вокруг, как в pi);
     на другой — загрузить каждый через `files_upload` на узел сессии и вставить пути;
  2. картинка: загрузить через `files_upload` на узел сессии, вставить полученный путь;
  3. текст: вставить.
- Ошибка чтения буфера — в строку статуса.
- Проверка: unit-тест на подменённом буфере (пути, картинка, текст; локальная и удалённая сессия).

## E. Состояние каждой вкладки

- `Workbench` хранит `TabView` по ключу `узел/сессия`:
  - черновик сообщения;
  - прокрутка: `follow` или якорь `{ key, offset }` (запись транскрипта и смещение в строках);
  - раскрытие вывода инструментов;
  - выбранный элемент (переносится сюда из нынешнего хранения в памяти);
  - видимая часть вывода задачи.
- TUI держит отдельный `Editor` на каждую открытую вкладку: при переключении сохраняются
  курсор, отмена, свёрнутые вставки, история.
- При уходе с вкладки TUI снимает якорь прокрутки (`lineOf`), при возврате восстанавливает;
  если якорь старше загруженного снимка — догружает ранние записи до него.
- Приложение: то же своими средствами (черновик поля, прокрутка `Transcript`, раскрытие).

## F. Сохранение между перезапусками

- Сохраняются: состояния вкладок (E), активная вкладка, выбранный узел (G).
- Хранилище подставляет интерфейс (`ViewStateStore` в `packages/client/src/workbench/`):
  - TUI: `~/.harness/ui-state/tui.json`, запись под lock со слиянием по ключу (два окна не
    затирают чужие вкладки; активная вкладка и узел — у окна, закрытого последним);
  - web: `localStorage`;
  - iOS/Android: файл через `expo-file-system`.
- Запись не чаще раза в 500 мс и при выходе. Записи удалённых сессий выбрасываются.
- Состояние окна принадлежит устройству и не синхронизируется между клиентами; набор вкладок —
  общий (`ui.tabs`).
- Курсор черновика после перезапуска встаёт в конец (в pi-tui нет публичной установки курсора).
- Пустые вкладки (K): без черновика не восстанавливаются; с черновиком — новая сессия в той же
  папке, черновик переносится в неё.
- Проверка: сценарий — набрать, прокрутить, переключиться и вернуться; перезапустить клиента —
  черновик, прокрутка, выбранный элемент, активная вкладка и узел на месте.

## G. Левая полоса из трёх блоков

- Правая полоса уходит целиком: `ItemsColumn` справа, `RIGHT_STRIP_MIN`, overlay `"items"`,
  действие `strip.items` (`Alt+→`), `ItemsStrip` справа в приложении, настройка
  `ui.web.panes.right` и её разбор.
- Заголовков «sessions» и «session» нет. Блоки разделены горизонтальной линией.
1. **Узлы** — высота по числу строк:
   - первым — узел этого окна (подпись `inprocess` у держателя, иначе `default`), затем
     удалённые и узлы за hub; последней строкой «+ add»;
   - глиф строки узла: `⊘` офлайн, `◆` хоть одна его сессия ждёт оператора, `●` что-то
     работает (считает `WorkbenchModel`);
   - «+ add» — привязка к hub на месте редактора: адрес и одноразовый код, обмен через
     `POST /pair`, токен в `remotes`; узлы за hub появляются сами.
2. **Сессии выбранного узла** — две трети оставшейся высоты; заголовков групп по узлам нет;
   выбор узла открывает его последнюю активную вкладку, а если вкладок на нём нет — выбор
   папки новой сессии (K) на этом узле; узел офлайн — строка статуса, выбор не меняется.
3. **Элементы активной сессии** — треть оставшейся высоты: первая строка `session` (цвет —
   режим, без подписи режима), ниже задачи и субагенты.
- Выбранный узел задаёт, где открывается новая сессия («+ new», Ctrl+T) и к какому узлу
  относятся действия HARNESS в панели.
- Ширина полосы — 18 колонок; длинные строки обрезаются с «…». На узком экране вся полоса —
  под одним overlay.
- Клавиатура: один курсор на всю полосу; `Alt+←` входит на активной сессии; ↑/↓ проходят все
  три блока; Enter открывает строку; Esc — в редактор. Клик, наведение, средняя кнопка — как
  сейчас.
- Приложение (`Shell.tsx`) — та же раскладка.
- Правки сценариев TUI, web и паритета под новую раскладку.

## H. madness, simple, implementer

- madness и simple — в сессии и в `harness.json` как значение для новых сессий (как сейчас);
  запись `harness.json` под lock.
- implementer — только в сессии: поле уходит из `harness.json`, из `Defaults`, из
  `saveDefault`; новые сессии начинают с `self`; старый ключ в файле не читается и исчезает
  при следующей записи.
- Проверки: `settings.test.ts` — implementer не пишется; сценарий — madness попадает в
  `harness.json`, implementer нет.

## I. Панель `Ctrl+\`

- Секции: MODE, SESSION, HARNESS.
- MODE: madness, simple.
- SESSION:
  1. Поле имени сессии — новый вид строки `text` в модели панели (`Workbench.panel`). Ввод
     начинается сразу, как только выбор попал на строку (стрелками или кликом). Имя применяется
     по мере набора через `set_session_name` с паузой ~400 мс (pi пишет запись на каждое
     изменение); при уходе из поля или закрытии панели — сразу. ↑/↓ уходят на соседние строки.
     Esc закрывает панель, сохранив имя. Новое имя видно во вкладке и у других клиентов.
  2. implementer — значение по кругу (`self` и профили субагентов).
- HARNESS: update, dependencies, subagents, logs, restart node.
- TUI рисует поле на месте строки; приложение — однострочный `TextInput` с теми же клавишами.
- Проверки: TUI и web — стрелками в поле, набор, имя во вкладке без Enter, ↓ уходит на
  implementer.

## K. Новая сессия

### Пустая сессия не сохраняется

- Пустая сессия — без единого сообщения пользователя или ассистента: то же правило, по которому
  pi не создаёт файл (`SessionManager._persist`; до первого сообщения все записи, включая имя,
  модель и записи harness, в памяти и пишутся разом с ним).
- Вкладка пустой сессии принадлежит только этому окну: в `ui.tabs` попадает с первым
  сообщением, тогда же её видят другие окна.
- Закрытие вкладки пустой сессии останавливает её агента сразу.
- Перезапуск: пустая вкладка без черновика не восстанавливается; с черновиком — новая сессия в
  той же папке, черновик переносится в неё.
- Пустые сессии не попадают ни в последние папки, ни в список сессий Ctrl+O (файла у них нет).

### Выбор папки

- Ctrl+T и «+ new» сразу добавляют в левую полосу строку `new session` на выбранном узле; агент
  не запускается, пока не выбрана папка. В зоне чата (main) — список выбора папки; на месте
  редактора — подпись клавиш:
  `↑↓ select · → open · ← up · type filter · enter create here · esc cancel`.
- Режим «последние» (первым):

  ```
   New session on default
   › har▏                                    ← фильтр; пустой: «type to filter» блёкло
  ▌ folder ⇒                                 ← всегда первый, фильтр его не скрывает
    ~/dotfiles/.pi/harness              2h  ›
    ~/projects/themakers/crea/showone   1d  ›
    ~/projects/harness-site             5d
  ```

  Строки — папки, где создавались сохранённые сессии, по времени создания самой новой сессии,
  новые сверху; путь с `~`, справа блёкло возраст.
- Режим «обзор» (после `folder ⇒` или →):

  ```
   New session on default · ~/projects
   › ▏
  ▌ · this folder                           ← всегда первый: создать здесь
    crea                                    ›
    contrib                                 ›
    scratch
  ```

  Строки — подпапки текущей папки по имени.
- `›` справа — у каждой папки, где есть подпапки, в обоих режимах.
- Скрытые папки (`.x`) показываются, только когда фильтр начинается с точки.

### Клавиши

Фокуса и полей нет, все клавиши у списка.

| Клавиша | Действие |
|---|---|
| печатные символы | дописываются в фильтр; список сразу сокращается нечётким поиском |
| Backspace | стирает символ фильтра; при пустом фильтре в «обзоре» — на уровень вверх |
| ↑ / ↓, PgUp / PgDn, Home / End | выбор строки |
| → | войти в выбранную папку: список заменяется её подпапками, фильтр очищается; на `folder ⇒` — обзор от домашней папки пользователя узла |
| ← | на уровень вверх (из домашней — к `/`); в «последних» ничего не делает |
| `/` | войти в верхнюю подходящую папку (`har/cr/` открывает `harness/crea`) |
| `~` или `/` первым символом в «последних» | обзор от домашней папки или от корня |
| Enter | создать сессию в выбранной папке (на `· this folder` — в текущей); на `folder ⇒` — как → |
| Esc | отмена: строка `new session` исчезает, возвращается предыдущая вкладка |

- После Enter агент запускается, фокус в редакторе, строка в полосе показывает имя папки.

### Мгновенность

- Узел отдаёт подпапки сразу с признаком «есть подпапки».
- Клиент заранее подгружает содержимое выбранной папки и её родителя: → и ← срабатывают без
  ожидания, в том числе для узлов за hub.
- В пределах одного выбора загруженные списки запоминаются.

### Мышь и касание

- Клик по строке — Enter, по `›` — →; наведение подсвечивает.
- В приложении в заголовке кнопка «←».
- С физической клавиатурой — как в TUI; на телефоне над списком видимое поле фильтра,
  клавиатура открывается касанием.

### Запуск `harness`

- `harness` — восстанавливает вкладки, активную вкладку и выбранный узел (F); если вкладок нет —
  выбор папки на выбранном узле.
- `harness <dir>` — то же и новая сессия в `dir` активной вкладкой (пустая вкладка-черновик до
  первого сообщения); `harness .` — в текущей папке оболочки.
- `-c` — последняя сохранённая сессия в указанной или текущей папке; `--session <id>` — сессия по
  id. Без изменений.
- Справка `harness --help` описывает это.

### Код

## L. MCP и компоненты расширений во всех клиентах

### Причина

- Агент сообщает расширениям `mode: "rpc"` (`bindExtensions` в `packages/agent/src/hap-server.ts`).
  Встроенное MCP-расширение pi вне `"tui"` на `/mcp` только печатает статус, а `/mcp login`
  открывает браузер на машине узла. Менеджер (`McpManagerView`) — компонент pi через
  `ctx.ui.custom()`: в TUI его показывает мост компонентов, в приложении — нет.

### Решение

1. Агент сообщает расширениям `mode: "tui"` (у harness всегда есть интерфейс оператора). `/mcp` открывает
   менеджер pi один в один (серверы и состояние, инструменты, переподключение, вход и выход,
   видимость, включение и выключение, в том числе для проекта; сохранение в `mcp.json` — pi).
   Проверено, кого затрагивает: в pi режим читают MCP и `llama` (его harness не подключает);
   magic-context в `"tui"` показывает статус записью в транскрипте (как в pi) вместо диалога.
2. Ссылки входа открывает клиент: `createMcpExtension({ openUrl })` в `packages/agent/src/runtime.ts` шлёт
   ссылку клиентам; TUI открывает её на своей машине и показывает кликабельной (OSC 8),
   приложение — браузером или `Linking`. Если клиент не на машине узла, OAuth-возврат на
   `127.0.0.1` не дойдёт — в менеджере pi есть поле для URL, на который вернул браузер.
3. Приложение показывает компоненты расширений как удалённый терминал (ниже). Это осознанное
   исключение из A25: чужие компоненты терминальные по природе; один механизм решает
   несовместимые диалоги системно. Записать в отступления плана платформы.
4. Когда у узла нет клиента, способного показать компонент, — строка статуса
   «extension <имя> waits for an interactive client»; компонент ждёт подключения и не возвращает
   `undefined` молча.

### Компонент в приложении

- Место: обычный компонент — на месте редактора, overlay — слоем поверх основной области
  (как в TUI). Моноширинный шрифт зоны chrome, цвета из ANSI. Над компонентом подпись
  `extension: <имя>`.
- ANSI → текст: `packages/client/src/ansi.ts` (без Node API) — SGR (16, 256, truecolor; жирный, курсив,
  подчёркивание, инверсия, тусклый), OSC 8 → кликабельные ссылки, служебные маркеры pi-tui
  (APC) выбрасываются, маркер курсора → видимый курсор.
- Размер: ширина в колонках по ширине зоны и символа шрифта, при каждом изменении;
  `harness_component_resize` получает `rows`, мост отдаёт их как `terminal.rows`; TUI тоже
  отправляет высоту.
- Захват ввода: пока компонент открыт, весь ввод его (как режим ввода `component` в TUI).
  Клавиши → байты терминала: стрелки, Enter `\r`, Esc `\x1b`, Tab, Shift+Tab `\x1b[Z`, Backspace
  `\x7f`, Delete, Home/End, PgUp/PgDn, Ctrl+буква, Alt — префиксом `\x1b`, печатные как есть; вставка —
  bracketed paste. Клавиши интерфейса (переключение вкладок, `Ctrl+\`) компоненту не передаются,
  как в TUI. Общая таблица кодирования — в `packages/client`, привязка — в
  `packages/app/src/keyboard.web.ts`.
- Мышь и касание: новое `harness_component_mouse { componentId, x, y, button, type }`; мост передаёт
  событие в `handleMouse` компонента (например, `SelectList`). Приложение переводит клик или
  касание в ячейку; TUI тоже передаёт мышь мосту (паритет).
- Телефон: под компонентом полоса кнопок ↑ ↓ ⏎ Esc Tab; касание строки — клик; кнопка
  клавиатуры открывает системную клавиатуру, набранное уходит в компонент посимвольно.
- Приложение объявляет возможность клиента `component-bridge`.

### Изменения

- Протокол (`hap.ts`, схемы, справочник): `rows` в `harness_component_resize`,
  `harness_component_mouse`.
- Агент: `mode: "tui"`; `createMcpExtension({ openUrl })`; мост — высота, мышь, ожидание
  интерактивного клиента.
- Клиент: `ansi.ts`, кодирование клавиш.
- Приложение: `ui/ComponentView.tsx` (на месте редактора и overlay), полоса кнопок для касаний.
- TUI: передача мыши и высоты мосту; открытие ссылок входа.
- Документация: отступление из A25 в плане платформы; `docs/extending/tools.md` —
  компоненты расширений во всех клиентах; `docs/pi-mapping.md` — `ctx.mode` теперь `"tui"`.

### Проверки

- unit: `ansi.ts` на эталонных строках (цвета, стили, OSC 8, маркеры); кодирование клавиш; мост —
  высота и мышь доходят до компонента.
- Сценарий web с `probe-extension` (компонент с `SelectList`): стрелки, Enter и клик выбирают;
  вставка доходит; смена ширины перерисовывает; overlay ложится поверх основной области.
- Сценарий TUI: то же плюс клик мышью.
- Сценарий `/mcp` в TUI и web на тестовом stdio MCP-сервере (`@modelcontextprotocol/server`):
  менеджер открывается, вход в сервер, переподключение, выключение — изменение в `mcp.json`.
- `openUrl` доходит до клиента.

## M. Claude-субагент выглядит как сессия harness

### Сейчас

- У Claude в основной области простой текст (`packages/tui/src/app.ts`, ветка `subagent`): заголовок,
  состояние, до 50 последних шагов одной строкой и последний текст. Данные едут в состоянии
  сессии (`SubagentInfo.steps/text`), которое рассылается целиком; история после перезапуска пропадает.

### Поток Claude → сообщения pi

- Чистая функция `claudeTranscript` в `packages/protocol/src/claude.ts`:

  | Claude | pi |
  |---|---|
  | `assistant`: блоки `text`, `thinking`, `tool_use` | `AssistantMessage`: text, thinking, toolCall |
  | `user`: `tool_result` | `toolResult` с `isError` |
  | сообщение оператора (steering) | сообщение пользователя |
  | `result` (стоимость, токены, итог) | запись harness — баннер конца прогона |
  | ожидание лимита, повторы API, отказ в правах | записи harness с нашими отрисовщиками |

- `TranscriptView` и приложение рисуют Claude теми же компонентами pi: markdown, thinking, раскрытие
  инструментов по Ctrl+E, поиск, прокрутка, подгрузка старых записей.

### Инструменты Claude → отрисовщики pi

- `Bash` → `bash` (`command`); `Read` → `read` (`file_path` → `path`, `offset`, `limit`); `Edit` → `edit`
  (`edits: [{ oldText, newText }]`, diff рисует pi); `Write` → `write`; `Grep`, `Glob` → `grep`, `find`;
  `mcp__harness__<tool>` → отрисовщик `<tool>`.
- Остальные (`WebFetch`, `TodoWrite`, внешние MCP и прочие) — общий вид pi для неизвестного
  инструмента (имя, аргументы, результат).

### Подагенты Claude (`Task`) — вложенно под вызовом

- События с `parent_tool_use_id` не выходят на верхний уровень: `claudeTranscript` собирает их в
  шаги того вызова `Task` (вызовы инструментов с результатами, текст, thinking). Пока
  подагент работает — частичные обновления результата `Task`; в конце — итог и все шаги.
- Отрисовщик `Task` (harness): свёрнуто — заголовок, счётчик шагов, последний шаг одной
  строкой, итог; раскрыто (Ctrl+E) — каждый шаг теми же компонентами pi со сдвигом вправо.
  Вложенный `Task` — рекурсивно тем же отрисовщиком.
- Строки подагентов Claude в левой полосе (под Claude, с отступом) остаются; их выбор
  прокручивает транскрипт Claude к этому вызову `Task` и раскрывает его.

### Живой стрим

- К запуску Claude добавляется `--include-partial-messages`; события `stream_event` → частичное
  сообщение (текст и thinking по мере генерации).

### Доставка и хранение

- Из `SubagentInfo` убираются `steps` и `text`; строка субагента и сводка остаются (глиф,
  состояние, модель, стоимость).
- Агент-родитель пишет события stream-json как есть в `~/.harness/claude/<session>.jsonl`
  (документированный формат; внутренние файлы Claude не читаются); отсюда история после
  перезапуска.
- HAP: `harness_subagent_snapshot { session, limit }`, `harness_subagent_entries_before { session, cursor,
  limit }`, живые записи `harness_subagent_entry` — только клиентам с открытым видом. Схемы,
  справочник.
- Клиент: Claude-субагент — такая же модель транскрипта (`AgentModel`), как сессия; текстовая ветка
  в TUI и приложении удаляется, зона main `subagent` всегда показывает транскрипт.

### Как сессия

- Редактор под транскриптом — steering Claude; запросы прав и ожидание лимита —
  interactions на месте редактора (как сейчас).
- Footer: модель Claude (`opus → claude-opus-5-5`), effort, стоимость, контекст из
  `result`/`usage`, состояние.
- Остающиеся отличия (возможности Claude Code): нет `/tree`, смены модели на ходу, `/compact` и
  прочих команд pi; `!bash` оператора недоступен.

### Проверки

- unit `claudeTranscript` на фикстурах (`usage-limit.jsonl`, `watchdog.jsonl`, `background-tasks.jsonl`) и
  новых: thinking, `Edit`, частичные события, `Task` с шагами подагента и вложенным `Task`
  (шаги внутри нужного вызова, не на верхнем уровне; частичные обновления по порядку).
- unit: перевод аргументов инструментов Claude в pi.
- Сценарий на поддельном `claude`, TUI и web: markdown, раскрытый `edit` с diff, стрим,
  steering; `Task` свёрнут (счётчик, последний шаг, итог), Ctrl+E или клик раскрывает;
  выбор строки подагента в полосе прокручивает к вызову; после перезапуска клиента история на
  месте; поиск по транскрипту.

### Порядок секций harness

- `assembleSystemPrompt` (`packages/extension/src/core/prompt.ts`) раскладывает `options.sections` явно:
  сначала наши в порядке `prompt.yaml`, затем чужие (`magic_context`, `mcp_servers` и другие) в
  порядке их появления. Порядок не зависит от загрузки расширений.

### Промпт Claude — тем же сборщиком

- `claudeSystemPrompt` заменяется сборкой тем же сборщиком с профилем `claude` в `prompt.yaml`:
  - преамбула Claude и роль из профиля;
  - `project_context` — ровно те файлы, что загрузил harness (`contextFiles` его промпта);
  - `skills` с путями (Claude читает SKILL.md своим Read), без брифинг-скиллов
    `subagent-*` (инструмента `subagent` у Claude нет);
  - `rules`: общие правила harness плюс правила каждого разрешённого инструмента из его
    `promptGuidelines` (или замены в `prompt.yaml`) под MCP-именем `mcp__harness__<name>`;
  - политика текущего режима (PLAN, BUILD, SIMPLE);
  - `engineering_principles`, `code_exploration`, `harness_docs`;
  - `<mcp_servers>` с тем же списком, что у harness, и пояснением: серверы codemode — через
    `mcp__harness__codemode` (`tools.mcp__<server>__…`), прямые — по именам `mcp__harness__…`.
- Правила, которые к Claude не относятся (`ctx_*`, магия контекста, `subagent`), исключаются явно в
  профиле `claude`.
- Базовые инструменты pi `read`, `bash`, `edit`, `write` через мост больше не отдаются (сейчас
  у builder нет `tools.allow`, и они дублируют родные `Read`/`Bash`/`Edit`/`Write`, а gate на родные уже
  стоит хуком). В профиле `claude` в `prompt.yaml` — таблица имён: `read`→`Read`, `bash`→`Bash`,
  `edit`→`Edit`, `write`→`Write`, остальные → `mcp__harness__<name>`; сборщик переписывает имена
  инструментов в текстах правил (`` `edit` `` → `` `Edit` ``) по этой таблице.
- Промпт собирается при каждом запуске Claude (в том числе `continue`/`--resume`) с режимом на момент
  запуска. Если режим меняется во время прогона, gate решает по новому режиму, а причина отказа
  хука называет его («harness is in PLAN mode: read-only»).
- Блок `claude` в `prompt.yaml` (преамбула) переписывается под инструкцию и план вместо brief.
- MCP-серверы напрямую в `--mcp-config` Claude не отдаются: одно подключение, входы
  `mcp-auth.json`, секреты, gate и правила — через мост.
- `--settings` Claude дополняется:
  `pluginConfigs["cc-plugin-agents-md@builtin"].options.instructionFiles = "managed-only"` (Claude не грузит
  сам `CLAUDE.md`/`AGENTS.md`) и `autoMemoryEnabled: false`.

    блок передачи работы называет его.

### Тесты

- Golden-тест системного промпта harness: стенд с собранным бандлом и тестовым MCP-сервером
  записывает настоящий запрос; пути store, рабочего каталога и id нормализуются; сравнение
  с `tests/fixtures/system-prompt.golden.md` и `tools.golden.json`; обновление — только явной командой.
- Инварианты промпта: порядок секций; каждый объявленный инструмент в `<tools>`, его
  правила в `<rules>`; пути скиллов и документации существуют в бандле; `mcp_servers`
  перечисляет сервер стенда; есть `magic_context`. В промпте Claude — ни одного имени базового
  инструмента pi в нижнем регистре, в мосту нет `read`/`bash`/`edit`/`write`, нет `subagent-*` скиллов.
- Тестовый MCP-сервер — тот же stdio-сервер на `@modelcontextprotocol/server`, что в L (один файл в
  testkit).
- Интеграции: инструмент тестового MCP-сервера вызывается из codemode; инструменты пакетов
  бандла в списке (`ctx_*`, ollama, deepseek, usage).
- Claude (поддельный `claude` записывает argv и `--settings`): каждая секция промпта; правила
  каждого разрешённого инструмента под MCP-именем; `project_context` как у harness; политика
  текущего режима; `<mcp_servers>`; в settings — `managed-only`, `autoMemoryEnabled: false`, хук и
  MCP-конфигурация; golden-файл промпта Claude.
- Claude вызывает инструмент тестового MCP-сервера через `mcp__harness__codemode` и получает результат.
- unit: разбор `plan` (нет файла, не `.md`, вне рабочего каталога и проекта, слишком большой);
  сборка первого сообщения; заметка с diff при изменённом плане.
- Сценарий на поддельном `claude`: первый вход — инструкция и план целиком; `continue` с
  изменённым планом — заметка и diff; в TUI вызов показывает ссылку на план.
- Тест промпта проверяет новые формулировки брифинга и правила implementer.

## Порядок реализации

Каждый шаг — отдельный коммит после зелёного `nix flake check`.

1. N — корректность ядра и golden-тесты первыми: остальные шаги меняют промпт и
   инструменты уже под их охраной (тестовый MCP-сервер появляется здесь).
2. A, B, D — локальные правки TUI.
3. C, J — узел внутри процесса и гонки.
4. H, I — настройки режимов и панель.
5. G, K — левая полоса и новая сессия.
6. E, F — состояние вкладок и его сохранение (поверх новой полосы и пустых вкладок).
7. L — компоненты расширений и `/mcp`.
8. M — Claude как сессия (поверх `<plan>` из N).
